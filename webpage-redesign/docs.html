man mailbrief

Command and configuration reference

Every command, subcommand and flag, the Telegram commands, and every setting. The long-form explanation of each step lives in commands.md, which stays the canonical reference. New here? Start with Setup.

Overview

Run every command from the project folder with uv run, which uses the project's own environment. No virtualenv activation is needed. In Docker the prefix is docker compose exec mailbrief instead, as in docker compose exec mailbrief mailbrief status.

mailbrief <command> --help prints each command's options with examples.

What MailBrief writes to Outlook. Only its own MB: categories (labels), when run, labels apply, labels clear or labels retag runs. Every request passes one check before it leaves your machine: reads are allowed, UpdateItem only when it changes nothing but Categories, and the category list may only gain or lose names starting with MB: . Moving, deleting, sending and marking read are refused before any network call.

Commands that never contact Outlook: emails (unless --send, which uses Telegram), events, rules, index, chat, stop, status, autostart. The Telegram chat fetches attachments from Outlook only when you tap a file button.

mailbrief global options

mailbrief [--help] [--version] <command> …
FlagDoes
--help, -hLists the commands and the first-time order. Works on every command and subcommand too.
--versionPrints mailbrief <version>.

The help ends with the first-time order:

mailbrief login                        # sign in to Outlook once
mailbrief add-destination telegram     # where the digest goes
mailbrief run --send --commit          # your first digest
mailbrief serve                        # then every morning by itself

Commands: login, run, emails, add-destination, labels, rules, index, chat, bot, events, serve, stop, status, autostart.

mailbrief login

mailbrief login [--remote]

Signs you in to Outlook once in a visible Chromium window. Sign in (MFA, tick Stay signed in), wait for your inbox, then press Enter in the terminal. Cookies, local storage and the browser's user agent are saved encrypted to data/session.enc. No email is read.

Run it again the first time, whenever run says the Outlook session expired, and after changing SESSION_ENCRYPTION_KEY. Sign in on the machine that runs the daily job; copied sessions often force a new sign-in.

--remote: sign in from any browser

For servers with no screen; the same as /login in Telegram. A headless Chromium opens Microsoft's sign-in page in a fresh profile, a small web server starts on $PORT (default 8080), and a one-time link is printed: https://<your-app>/login#<token>. Open it, tap Start, and drive the live picture: tap to click, type in the box and press Send, use the Enter, Tab and ⌫ buttons. When the inbox appears, the session is saved and checked, and you get Logged in ✅.

  • The token sits after #, so it never reaches a server log. Tapping Start spends it and gives your browser a private cookie; a forwarded link does nothing.
  • The page stays open for at most 10 minutes and closes as soon as you're signed in.
  • https:// only, except http://localhost, which listens on this machine only. On your PC, a blocked 8080 falls back to a free port; on a server, or with PUBLIC_URL set, it reports the blocked port instead.
  • Your inbox is never pictured, and screenshots and typing stay in memory.
  • It holds the run lock, so it and a run wait for each other.
  • The link's address is PUBLIC_URL, else RENDER_EXTERNAL_URL, else https://$RAILWAY_PUBLIC_DOMAIN, else http://localhost:$PORT.
  • From your phone while MailBrief runs on your PC: install cloudflared, set LOGIN_TUNNEL=cloudflared, restart serve and send /login. The link is a temporary trycloudflare.com address. Cloudflare sees the traffic, your password included.
winget install --id Cloudflare.cloudflared

CodeMeaning

1--remote: timed out, or the saved sign-in didn't work
2--remote: PUBLIC_URL isn't https://, the port is in use or blocked, or cloudflared didn't start within 30 s

mailbrief run

mailbrief run [--all] [--backfill] [--digest SCOPE] [--as-of YYYY-MM-DD]
              [--json] [--send] [--commit] [--plain] [--quiet]

Opens Outlook headless and finds inbox emails since the last committed run (24 hours back when there is no cursor). It fetches full text and images, classifies each email with the AI using thread context, saves everything to the encrypted archive, puts MB: labels on the emails in Outlook, writes the digest and prints it. Nothing is sent without --send, and nothing is marked processed without --commit. Emails already in the archive never go to the AI again. Emails the AI failed on in the last 7 days are retried.

Progress goes to stderr as [mm:ss] lines. With no new mail and no --digest, it prints No new emails, so no digest. Only one run happens at a time (data/run.lock, released by the OS even after a crash).

FlagDoes
--allProcesses every inbox email, ignoring the cursor. Saved emails reuse their classification. The digest still covers only new mail unless you add --digest.
--backfillSaves the whole inbox to the archive. Implies --all; no digest unless --digest is given; oldest conversations first; saves every 25 emails, so Ctrl+C keeps progress; resumable; advances the cursor to the newest email at the end.
--digest SCOPEWhat the digest summarises: new (default), this-week, this-month, last-month, older, all. Period scopes are read from the archive. Over 40 emails, it summarises parts of 25 (4 at a time) and merges them. Period digests use the headings STILL OPEN, DEADLINES & MEETINGS, KEY EVENTS, NOISE.
--as-of YYYY-MM-DDWith a period scope: count the period from that day instead of today. serve uses it to catch up a missed summary.
--jsonPrints the selected emails as a JSON array on stdout (full body and classification); everything else goes to stderr. Prints [] on a quiet day. The output is unencrypted email text.
--sendSends the digest to every active destination, then the UPCOMING EVENTS calendar (unless EVENTS_DAYS=0). Every bullet links to its email. Long digests are split per section, tagged · k/n, paced 0.5 s apart, with 429 retries.
--commitAdvances the cursor so these emails aren't shown again. Refused when only list previews were read or the archive couldn't be saved (exit 4), or when --send reached no destination (exit 1).
--plainSaves this run's month files as plain YYYY-MM.json instead of encrypted .enc. A later run without it re-encrypts the months it touches. --no-password is the old name and still works.
--quietLeaves out email lines and digest text; only progress, counts and results print. serve uses it so logs hold no email content.
 
uv run mailbrief run                             # preview: nothing sent or marked processed
uv run mailbrief run --send --commit             # the daily job
uv run mailbrief run --digest this-month         # month summary from the archive
uv run mailbrief run --backfill --digest all     # archive everything, then summarise it
uv run mailbrief run --json > today.json         # export (unencrypted)
Exit codes
CodeMeaning
0Success, including no new mail
1Cursor not advanced: the digest reached no destination
2No saved session, or it expired: run mailbrief login
3Another run is in progress; nothing done
4Digest sent, but --commit refused (previews only, or archive not saved); the cursor is kept
5Outlook opened, but its inbox list couldn't be read (usually an Outlook format change)

mailbrief emails

mailbrief emails [--period P] [--day YYYY-MM-DD] [--search TEXT]
                 [--show N | --thread N] [--digest [--send]] [--export FILE]

Browses the saved archive offline: no Outlook, no AI. Without flags it lists this week's emails grouped by thread, newest activity first, replies indented with ↳, your messages as You, answered ones marked ✓ replied. The footer counts inbox emails per period.

FlagDoes
--period Pthis-week (default), this-month, last-month, older. Computed from the received date when you view.
--day YYYY-MM-DDEmails received that day, in DEFAULT_TIMEZONE.
--search TEXTCase-insensitive match in sender name, address, subject or body, across all periods unless --period is given.
--show NOpens email #N of the same filtered list: headers, classification, summary, action items, deadline, your labels, thread outline, full body.
--thread NPrints the whole conversation of email #N. Cannot be combined with --show.
--digestPrints the digest(s) saved on --day (default today), each headed with its scope and time.
--sendWith --digest: resends the latest saved digest to all destinations, split as run --send would, plus a fresh events calendar. No Outlook, no AI. Without --digest it is rejected (exit 2).
--export FILEWrites the listed emails to FILE as plain, unencrypted JSON.

Filters combine freely. Use the same filters with --show and --thread as when you listed, so the numbers match.

uv run mailbrief emails --search fee
uv run mailbrief emails --search fee --show 2
uv run mailbrief emails --digest --day 2026-10-16 --send

Exit codes: 0 OK (also nothing matched); 1 N out of range, a file can't be decrypted, or a resend had no digest or reached no destination; 2 bad --day, or --send without --digest.

mailbrief events

mailbrief events [--days N] [--past N] [--send]

The UPCOMING EVENTS calendar, built by code from the events the classifier saved for each email. No Outlook, no AI. Grouped by day, soonest first; boosted ⭐ events first within a day; the same event in two emails is shown once. Undated events only appear in the morning message on the day their email arrives.

FlagDoes
--days NHow far ahead, 0 to 365 (default EVENTS_DAYS, 14). --days 0 needs --past.
--past NAlso the last N days (0 to 365), headed like MON 13 OCT (PAST).
--sendSends exactly what would be printed to all destinations.

Older mail has no events until it is reclassified with labels retag. Exit codes: 0 done or nothing found; 1 archive unreadable or --send reached no destination; 2 --days/--past outside 0–365, or --days 0 without --past.

mailbrief labels

mailbrief labels {status | apply | clear | retag} …

MailBrief's classification as Outlook categories, visible on web, desktop and phone. Each inbox email gets a category label and a priority label. Your own categories are never touched; only MB: ones are swapped. Read state, folder and flags don't change. Search Outlook with category:"MB: Urgent".

CategoryColourPriorityColour
MB: UrgentredMB: P1dark red
MB: Needs ReplyorangeMB: P2orange
MB: MeetingspurpleMB: P3yellow
MB: FYIblueMB: P4teal
MB: NewslettergreenMB: P5grey
MB: Low Prioritygrey

Every run labels archived emails whose labels are out of date, up to 400 per run, unless OUTLOOK_LABELS=off. Labels you remove by hand aren't put back. Only inbox emails from other people with a real classification are labelled.

Exit codes for all subcommands: 0 done, nothing to do, or dry run; 1 you answered no (or no terminal and no --yes), or the archive or data/rules.json can't be read; 2 bad options or Outlook needs mailbrief login; 3 a run is in progress.

labels status

mailbrief labels status

Per period (this-week, this-month, last-month, older, all): emails labelled, pending (the next run labels them) and cleared (you removed them; left alone until apply).

labels apply

mailbrief labels apply [--period P] [--days N] [--limit N] [--dry-run]

Labels now: everything pending, plus emails you cleared. Re-creates the coloured categories if you deleted them. After adding a course or sender rule, --dry-run shows which emails will get it.

labels clear

mailbrief labels clear (--period P | --days N | --all | --label NAME)
                       [--limit N] [--colours] [--everywhere] [--dry-run] [--yes]

Removes MB: labels; your own categories stay. Shows how many emails and asks Go ahead? [y/N]. Cleared emails stay cleared on later runs; new mail is still labelled.

FlagDoes
--period Pthis-week, this-month, last-month, older
--days NEmails from the last N days
--allEvery email MailBrief labelled
--coloursAlso deletes the 11 MB: categories from your category list, which strips them from every email
--label NAMEOnly one of your own labels (all periods by default). Refused while a rule still gives it, and for built-in labels
--everywhereWith --label: from every email in the mailbox and your category list; ignores --period/--days/--limit
--limit NAt most N emails, newest first
--dry-runShows what would change without touching Outlook
--yesSkips the confirmation

labels retag

mailbrief labels retag (--period P | --days N) [--limit N] [--dry-run] [--yes]

Asks the AI again about saved emails, with your current profile and topics, and updates their labels and events. About one AI call per email; it asks first. Images are fetched again (opening Outlook when needed). Failed calls keep the old classification. --dry-run shows how many emails and calls; --limit N caps the emails, newest first.

mailbrief rules

mailbrief rules {list | add | remove | profile} …

Your own labels, beside category and priority, stored in data/rules.json (plain JSON, git-ignored, editable by hand). Sender rules name their label with --label; see rules add. A broken file never stops the digest: the run warns, classifies without rules and skips Outlook labelling that run.

KindMatched byGives
courseCode, no AI: the code as a whole word in subject, sender name or first 1,000 body charactersMB: CS1101S
senderCode, no AI: an exact address, or part of the sender's name (no @)MB: Prof Tan
topicAI: the classifier picks matching topic namesMB: Networking
profileAI: who you are; used for priority and boosts(no label)

Course and sender rules apply to the whole archive on the next run or labels apply. Topics and the profile apply to new mail; use labels retag for older mail. Names are up to 40 characters, without , or ;, and can't be a built-in label. Exit codes: 0 done; 1 rule not found or rules.json unreadable; 2 bad rule.

rules list

mailbrief rules list

Your rules and profile, with how many saved emails each matches. Shows the exact error if rules.json is broken.

rules add

mailbrief rules add {course | sender | topic} KEY [DESCRIPTION]
                    [--label NAME] [--direct] [--priority 1-5] [--boost]
Argument / flagDoes
KEYCourse code, sender address (or part of a name), or topic name
DESCRIPTIONTopic only: what counts, in plain words
--label NAMESender only: the label to give, e.g. "Prof Tan"
--directSender only: only mail where you are the only To recipient
--priority 1-5Matching mail is at least this priority (1 most urgent)
--boostCourse or sender: always list under OPPORTUNITIES & EVENTS with ⭐ (and at least P2)

Adding the same key again replaces the rule. Topic labels boost an email when the AI also judges it fits your profile.

uv run mailbrief rules add course CS2103T --priority 2
uv run mailbrief rules add sender tan@example.edu --label "Prof Tan" --direct --priority 1
uv run mailbrief rules add sender "Career Centre" --label Careers --boost
uv run mailbrief rules add topic Networking "career fairs, meetups, recruiter outreach" --priority 2

rules remove

mailbrief rules remove {course | sender | topic} KEY

Removes the rule. Emails already labelled keep the label; take it off with labels clear --label NAME.

rules profile

mailbrief rules profile TEXT

Sets who you are and what you want, e.g. "Year 2 CS student looking for internships". "" clears it. The classifier and the digest both see it.

mailbrief add-destination

mailbrief add-destination telegram [--chat-id ID]

Registers where digests go and who may chat with the bot. Destinations can only be added this way, from your machine. Interactive: message your bot first, then pick your chat from a single getUpdates lookup; a test message is sent. --chat-id ID skips the lookup and the test message. Stop serve first, or use --chat-id, because Telegram allows one reader at a time.

Writes data/destinations.json. Adding the same chat replaces it; set "active": false by hand to pause one. Exit codes: 0 added; 1 no chats found or invalid choice; 2 unknown type (only telegram exists).

mailbrief index

mailbrief index {status | update | rebuild}
  • status: counts only (emails, chunks, model, size, last update).
  • update: embeds new or changed emails. Runs do this by themselves.
  • rebuild: embeds everything again, e.g. after changing AI_EMBED_MODEL.

Every saved email with full text is cut into a header chunk plus body chunks of about 1,500 characters (at most 6) and sent to AI_EMBED_MODEL at AI_BASE_URL. Vectors and hashes are stored encrypted in data/index.enc, with no email text; it is safe to delete. Exit codes: 0 done; 1 archive unreadable or nothing indexed; 3 a run is in progress.

mailbrief chat

mailbrief chat ["QUESTION"]

Asks your saved emails in the terminal, as the Telegram chat does. With a question it answers once; without, it keeps asking until an empty line or Ctrl+C. Answers carry [n] refs and a numbered Sources list with Outlook links, or Closest matches when nothing was cited. Follow-ups work within a session. Needs the index; no Outlook is opened. Exit codes: 0 done; 1 no index yet or archive unreadable.

mailbrief bot

mailbrief bot

Runs only the Telegram chat listener in the foreground, without the scheduler, until Ctrl+C. For testing; serve already runs it. Exit codes: 0 stopped; 2 CHAT=off or no bot token; 3 serve is running.

mailbrief serve

mailbrief serve [--at SCHEDULE]

Runs forever and fires runs on the RUN_AT schedule, plus the Telegram chat when CHAT=on. --at "daily 18:00" tries a schedule without editing .env.

  • Checks the clock every 30 s, so it notices wake-ups. Missed slots run once serve is back: only the latest per scope. No catch-up on the very first start.
  • Each run is a child process with a 45-minute limit. A failed run is retried after 15 minutes, up to 3 attempts, then you get one Telegram message (at most once a day).
  • An expired login isn't retried: you get one Telegram message a day asking you to send /login.
  • Scheduled runs use --quiet, so data/logs/ never holds subjects or digest text.
  • Stopping (Ctrl+C, mailbrief stop, docker compose down) lets a run in progress finish, including a /sync run. A second Ctrl+C stops at once.

Exit codes: 0 stopped normally; 2 bad schedule; 3 already running; 130 forced stop.

mailbrief stop

mailbrief stop

Asks a running serve (hidden, or in another terminal) to stop. Idle, it stops within a second. During a run it waits up to 10 s, then tells you it is finishing the current run. Exit code 0. To stop only a run and keep serve going, in PowerShell:

Get-CimInstance Win32_Process -Filter "CommandLine LIKE '%mailbrief.main run%'" | ForEach-Object { Stop-Process -Id $_.ProcessId }

mailbrief status

mailbrief status

Whether serve is running (pid, since when), the schedule, next run, last run and its result (ok, login needed, sent, but not marked processed (cursor kept), failed (exit N)), autostart state and the log file. Exit code 0.

mailbrief autostart

mailbrief autostart {on | off}

Windows only. on creates a Task Scheduler task named MailBrief that starts serve hidden (pythonw) at logon, as you, on battery too, with no time limit. off removes it; a running serve keeps going until mailbrief stop. Start it now with schtasks /Run /TN MailBrief. No admin rights needed. Exit codes: 0 done; 1 Task Scheduler refused; 2 not Windows.

Telegram commands

The chat runs inside serve (or bot) by long polling: no webhook, no open port. Only your registered private chats get answers; everyone else and every group is ignored. Anything that isn't a command is a question about your email, answered with ↗ links, a Sources list and buttons for the sources' attachments. The last 3 questions and answers per chat are kept in memory only.

CommandWhat it does
/start, /helpWhat the bot can do
/newForgets this conversation
/syncChecks for new mail now: a normal run with --send. With nothing new: ✅ No new mail since the last check. It reports a busy run, an expired login, an undelivered digest or a timeout in plain words
/loginA one-time sign-in link (as login --remote) for when the Outlook login expires
/digestSends the latest saved digest again, with links, then the events calendar
/events [days]The upcoming events calendar; days 1 to 365 (default EVENTS_DAYS, or 14 when that is 0)
/rules (old name /labels)Your label rules, as mailbrief rules list
/rule (old name /label)/rule add course CS2040S [p2] [boost]
/rule add sender a@b.c "Prof X" [direct] [boost] [p1]
/rule add topic Networking "career fairs, meetups" [p2]
/rule remove course|sender|topic KEY
/profile textSets your profile, as mailbrief rules profile

Unknown commands get I don't know /x. /help lists what I can do. Tapping an attachment button fetches the file from Outlook in memory and sends it; buttons expire when serve restarts. /rules is about your own labels; mailbrief labels is the Outlook categories.

RUN_AT schedule

RUN_AT   = entry { ";" entry }
entry    = days " " time [ " " scope ]
days     = day { "," day }
day      = daily | weekdays | weekends | mon | tue | wed | thu | fri | sat | sun | day-N   (N = 1..31)
time     = H:MM or HH:MM, 24-hour, in DEFAULT_TIMEZONE
scope    = new | this-week | this-month | last-month | older | all      (default new)

Day names and scopes are case-insensitive. A new entry runs run --send --commit --quiet. Any other scope runs run --send --quiet --digest <scope> without --commit, so a weekly summary doesn't hide mail from the next daily digest. day-31 fires only in months with a 31st. A bad schedule is refused before anything starts (exit 2), e.g. Bad schedule: 'daily 7.30': time must look like 07:30.

RUN_AT=daily 07:30
RUN_AT=daily 07:30; daily 18:00
RUN_AT=weekdays 08:00; weekends 10:00
RUN_AT=mon,wed,fri 07:30
RUN_AT=daily 07:30; sun 20:00 this-week; day-1 09:00 last-month

Hosting

A server runs the same serve in Docker. The repo has a Dockerfile (Python 3.11, uv, Chromium, non-root) and compose.yaml (restart: unless-stopped, a 10-minute stop grace period, ./data as a volume, shm_size: 1gb). The image needs about 2 GB of disk.

Docker on your own server

git clone https://github.com/KidCoderT/mail-manager.git
cd mail-manager
docker compose up -d --build
docker compose logs -f
docker compose exec mailbrief mailbrief status
docker compose down

Copy .env, data/session.enc and data/destinations.json across first (same key), or sign in with /login. For /login on a home server, uncomment the ports: line in compose.yaml and set PUBLIC_URL to an https:// address behind a TLS proxy or tunnel.

A cloud host sees your mail. Railway and Render hold data/ on their volume and SESSION_ENCRYPTION_KEY as a variable, so they have both the ciphertext and the key. Check your organisation's policy first. Your own PC or server keeps mail in-house. Both hosts build the Dockerfile directly and ignore compose.yaml, so suspect Docker's 64 MB /dev/shm if Chromium crashes. Microsoft sign-ins from datacenter IPs may expire sooner.

Railway

  1. New project from the GitHub repo; Railway builds the Dockerfile. Pick the region nearest you.
  2. Add a volume mounted at /app/data. If runs fail with "permission denied" there, add RAILWAY_RUN_UID=0.
  3. Variables: SESSION_ENCRYPTION_KEY, AI_BASE_URL, AI_API_KEY, TELEGRAM_BOT_TOKEN, TZ, RUN_AT and the rest of your .env.
  4. Networking: generate a domain and type port 8080 by hand. Set no healthcheck path: nothing listens until a sign-in starts.
  5. In the service shell, run mailbrief add-destination telegram --chat-id <your chat id>, then mailbrief login --remote and open the link. Later sign-ins: /login.

Render

  1. New Web Service from the repo; Render detects the Dockerfile. The free plan can't run MailBrief (it sleeps and has no disk): use Starter or above, and Standard if Chromium runs out of memory.
  2. Add a disk mounted at /app/data (1 GB is plenty).
  3. Environment: SESSION_ENCRYPTION_KEY, AI_BASE_URL, AI_API_KEY, TELEGRAM_BOT_TOKEN, TZ, RUN_AT. Render sets PORT and RENDER_EXTERNAL_URL. Leave the health check path empty.
  4. Render requires an open port, so serve keeps the sign-in server up on $PORT, answering 404 except to an open sign-in.
  5. In Shell, run mailbrief add-destination telegram --chat-id <your chat id>, then send /login. (login --remote can't run there: serve holds the port.)

To keep your history on either host, copy your PC's data/ across (same key); otherwise mailbrief run --backfill refills it. Any other host that insists on an open port: LOGIN_PAGE=always.

Recipes

First time

Common questions

What does it cost?

MailBrief is free, open-source software under the MIT licence. Creating a Telegram bot is free. Your AI endpoint may charge for classification, digests, chat and embeddings; running your own models uses your own hardware. A rented server is an additional cost. There is no MailBrief subscription.

Does it need an app registration?

No Microsoft app registration is needed: MailBrief uses your existing Outlook web session. That does not grant permission to automate a mailbox. Check your organisation's policy on automation, AI endpoints and Telegram before starting.

Does it work on macOS or Linux?

The established paths are Windows and the Linux Docker image. The Python and Playwright code should also run on macOS, but macOS is not regularly tested. The autostart command is Windows-only; use Docker or your own service manager elsewhere.

How do I remove it?

Stop the scheduler first. While your Outlook session still works, remove MailBrief's categories:

uv run mailbrief stop
uv run mailbrief labels clear --all --colours

If you enabled Windows autostart, run uv run mailbrief autostart off. Stop any separately running bot or container too. You can then delete the project folder and its data/ archive, remove any separately configured startup service, and revoke your Telegram bot token through @BotFather. Deleting the local archive is permanent; your emails remain in Outlook. Your own non-MB categories are untouched.

What if I lose the encryption key?

The saved session and archive can no longer be read. Generate a new key, sign in again, and rebuild from the emails still in Outlook with uv run mailbrief run --backfill, then uv run mailbrief index rebuild. Previously saved digests cannot be recovered without the old key; the original emails are untouched.

Privacy & limits

  • Stays on your machine: the browser session, the encrypted archive and the search index.
  • Leaves it: email text and images go to AI_BASE_URL; digests, chat answers, quotes and requested files go to Telegram, whose bot chats aren't end-to-end encrypted. CHAT=off turns the chat off.
  • Optional sign-in tunnel: with LOGIN_TUNNEL=cloudflared, the tunnel provider can see the remote sign-in page traffic, including what you type. On a rented server, the host holds both the encrypted archive and its key.
  • Linked images: with REMOTE_IMAGES=on, senders' image servers see your IP.
  • Prompt injection: the answering model reads email bodies but has no tools, can only reply in your chat, and never writes links; code builds them.
  • Outlook links work only for someone signed in to your mailbox. Opening one marks the email read, as Outlook always does.
  • Limits: Microsoft 365 on outlook.office.com only; it depends on Outlook's internal formats, which change; sign-ins expire on your organisation's schedule; one user; autostart is Windows-only.
