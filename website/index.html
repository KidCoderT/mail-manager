What it is, and who it is for

A university or work inbox mixes three things: the few emails that need you today, a steady stream of announcements, and newsletters with an event buried in the fourth paragraph. Sorting that by hand every morning takes time, and the costly mistakes are the quiet ones: a deadline you scrolled past, a professor still waiting for an answer.

MailBrief does the first pass for you. It is a Python command-line tool you run yourself, for your own mailbox. It is aimed at students and staff with a Microsoft 365 account who are comfortable with a terminal and already have, or can get, an AI endpoint they trust with their email text.

What it does

  • Classifies every new email One of six categories (Urgent, Needs Reply, Meetings, FYI, Newsletter, Low Priority) with a priority from P1 to P5, a one-line summary, action items and a deadline.
  • Labels the mail inside Outlook Coloured MB: categories that show on web, desktop and phone. Your own categories are left alone.
  • Applies labels you define Course codes, particular senders, and topics you describe in plain words, each with an optional minimum priority.
  • Sends a digest to Telegram Then a rolling 14-day calendar of the events your emails announce, including ones that only appear on a poster image.
  • Answers questions about your mail In the same chat, quoting the emails, listing its sources, and linking each one back to the email in Outlook.

A day with it

  1. 07:30

    The scheduled run starts. Nothing to click. It reads only mail that arrived since yesterday's run.

  2. 07:31

    The digest arrives in Telegram, then the events calendar. You read both on the way in.

  3. 09:00

    You open Outlook. Everything is already labelled, so you filter to MB: Needs Reply and answer two people.

  4. 13:40

    You ask the bot when the midterm is and what you may bring. It answers with quotes and a link to each email.

  5. 21:00

    A new course starts next week, so you send /label add course DES120. Matching saved mail is labelled on the next run.

How it works

Five steps, all started from your machine. The table shows each step and exactly what crosses to the three outside services: Outlook on the web, the AI endpoint you configure, and Telegram.

What stays on your machine

There is no database and no server component. Everything lives in a data/ folder next to the code, which git ignores.

data/session.encYour Outlook web session. Encrypted. Treat it like a password: it gives full access to the mailbox.
data/archive/YYYY-MM.encEach month's emails, classifications and digests. Encrypted. Kept until you set ARCHIVE_DAYS.
data/index.encSearch vectors for chat. Encrypted. No email text; rebuildable from the archive.
data/rules.jsonYour own labels and profile. Plain JSON. No email content.
data/logs/Service log: progress, counts, timings. Never subjects, digests, questions or answers.
.envYour keys and settings. Holds the encryption key, so encryption protects copies of data/, not someone already logged in as you.

Labels in Outlook

Each inbox email gets two labels, a category and a priority, plus any of your own.

MB: Low Priority

Your own: courses senders topics

  • Categories live on the server, so they show in Outlook on the web, desktop and phone. Filter with category:"MB: Urgent".
  • MailBrief reads an email's categories first and swaps only the MB: ones.
  • Read state, folder and flags stay as they were. Senders are not notified.
  • To undo everything: mailbrief labels clear --all --colours.

Terminal

  • Each phase reports progress with the time since the start, so a slow step is visible instead of looking stuck.
  • Add --send to deliver the digest to Telegram and --commit to mark these emails as processed. Together they are the daily job.
  • --commit refuses to advance if the digest reached no destination, so a failed delivery never loses a morning's mail.
  • Scheduled runs use --quiet, which leaves subjects and digest text out of the log.

Using it

Once it is set up you mostly leave it alone. These are the commands you will actually reach for. Run them from the project folder with uv run. The full list is in the command reference.

In the terminal

CommandWhat it does
mailbrief runPreview: read new mail, classify, label, print the digest. Nothing is marked processed.
mailbrief run --send --commitThe daily job: send the digest to Telegram, then mark the mail processed.
mailbrief run --digest this-weekA summary of a period: this-week, this-month, last-month, older or all.
mailbrief serveRun on the schedule and answer the Telegram chat, until stopped.
mailbrief statusIs the service running, when is the next run, how did the last one go.
mailbrief stopStop a running serve. A run in progress finishes first.
mailbrief emailsBrowse saved mail offline, grouped by thread. --search, --show N, --thread N, --digest.
mailbrief eventsPrint the events calendar. --days N, --past N, --send.
mailbrief chat "…"Ask a question in the terminal instead of Telegram.
mailbrief labels statusHow many emails are labelled or pending. Also apply, clear, retag.
mailbrief rules listYour own labels. Also add, remove, profile.
mailbrief loginSign in again when the session has expired.

Your own labels

Beyond the six built-in categories you define rules of your own. They are stored in data/rules.json and you can change them from the terminal, from the chat, or by editing the file.

KindDecided byExample label
CourseCode: the course code appears as a whole word in the subject, sender name or start of the body.MB: BIO204
SenderCode: an exact address or part of a name. --direct limits it to mail where you are the only recipient.MB: Dr Vastari
TopicAI: you describe what counts, and the classifier tags mail that fits. Only names from your list are accepted.MB: Research
ProfileAI: a sentence about you. It shapes priorities and what gets a ⭐.no label

A rule can set a minimum priority ("at least P2"). Course and sender rules apply to all saved mail on the next run, with no AI calls. Topic and profile changes apply to new mail; mailbrief labels retag --period this-month re-asks the AI for older mail.

# in the terminal
uv run mailbrief rules profile "Second-year biology student looking for lab internships and research talks"
uv run mailbrief rules add course BIO204
uv run mailbrief rules add course STAT310 --priority 2
uv run mailbrief rules add sender ivastari@example.edu --label "Dr Vastari" --direct --priority 1
uv run mailbrief rules add sender "Careers Office" --label Careers --boost
uv run mailbrief rules add topic Research "lab openings, research talks, summer studentships, poster sessions" --priority 2
uv run mailbrief rules list
# the same, sent to your bot
/label add course BIO204
/label add sender ivastari@example.edu "Dr Vastari" direct p1
/label add topic Research "lab openings, research talks, summer studentships" p2
/label remove course DES120
/profile Second-year biology student looking for lab internships

The schedule

mailbrief serve reads RUN_AT from .env. Entries are separated by ; and each one is <days> <HH:MM> [scope], in your DEFAULT_TIMEZONE.

PartAllowed values
daysdaily, weekdays, weekends, mon to sun, day-N (day of the month). Comma lists mix: mon,day-15
time24-hour HH:MM
scopenew (default), this-week, this-month, last-month, older, all
  • If the machine was off or asleep at a scheduled time, the run happens when serve is next running. Three days off means one digest covering all three, not three digests.
  • A failed run is retried after 15 minutes, up to 3 attempts.
  • Only a new entry marks mail as processed. A weekly summary does not hide anything from the next daily digest.
# .env: pick one
RUN_AT="daily 07:30"
RUN_AT="daily 07:30; daily 18:00"
RUN_AT="weekdays 08:00; weekends 10:00"
RUN_AT="daily 07:30; sun 20:00 this-week; day-1 09:00 last-month"
# try a schedule without editing .env (Ctrl+C stops it)
uv run mailbrief serve --at "daily 07:30; sun 20:00 this-week"

Privacy and safety, stated plainly

MailBrief handles your email, so here is what it does with it, including the parts that are not private.

  • The browser is local.

    Mail is read by a Chromium that runs on your machine, using the Outlook web session you already have. No app registration is needed, and no MailBrief server sits in the middle, because there is none.

  • It only adds labels.

    The one change MailBrief makes in your mailbox is setting its own MB: categories. Every request to Outlook passes a check in code first; anything that would move, delete, send, mark as read or create a rule is refused before it leaves your machine. There is no delete code path.

  • Saved mail is encrypted at rest.

    The session, the archive and the search index are encrypted with a key you generate. This protects copies of data/ (backups, sync folders, an accidental commit). It does not protect against someone logged in to your computer as you, who can also read .env.

  • Email text goes to the AI endpoint you choose.

    Classification sends each new email's text and some of its images. Chat sends your question and the text of about a dozen matching emails. Search sends email text to make vectors. What that provider keeps or logs is governed by its policy, not by MailBrief. An endpoint run by your own organisation, or a model on your own machine, keeps it closest to home.

  • Telegram sees what the bot sends.

    Digests are summaries. Chat answers go further: they contain quotes, and files when you ask for them. Bot chats are not end-to-end encrypted. CHAT=off makes the bot send-only.

  • Linked images can be switched off.

    To read event posters in newsletters, MailBrief downloads images the email links to. Those servers then see your IP address and when the mail was processed. Downloads are https only, refuse private network addresses, follow no redirects and carry no cookies. REMOTE_IMAGES=off stops them entirely.

  • Emails are treated as untrusted input.

    The models that read email have no tools: they can only return text. Links are built by code from email ids, never taken from model output. A file is only sent if it is an attachment of an email the answer cited.

  • The bot answers only you.

    Chats are registered from your terminal with mailbrief add-destination. The bot cannot add a chat itself and ignores everyone else silently. The bot token is a password: keep it in .env.

  • The phone sign-in page is optional.

    /login opens a temporary page showing MailBrief's own browser on Microsoft's sign-in screen. The link works once, binds to the first browser that taps Start, requires https, closes after 10 minutes, and never shows your inbox. With the optional LOGIN_TUNNEL=cloudflared, the tunnel provider can see that page's traffic, including what you type.

  • A cloud host is a third party.

    If you run MailBrief on a rented server, that host holds your archive, your session and the key that decrypts them. Your own always-on PC or your own server is what keeps mail in-house.

Limits, and a disclaimer

  • Unofficial. MailBrief is a personal project. It is not affiliated with, endorsed by or supported by Microsoft or Telegram. Outlook, Microsoft 365 and Telegram are named here only to describe what the tool works with.
  • It relies on an undocumented interface. MailBrief talks to Outlook on the web the way the web page does. Microsoft can change or block that at any time, and the tool can stop working without warning.
  • Check your organisation's rules first. Automating a work or school mailbox, and sending its contents to an AI endpoint and to Telegram, may or may not be allowed by your IT acceptable-use policy. Using your existing web session does not make it approved. Finding out is your responsibility.
  • Your own mailbox only. Use it on an account that is yours.
  • No warranty. Released under the MIT licence, as is.

What it does not do

  • Microsoft 365 work and school accounts only. No personal Outlook.com accounts, no Gmail or other providers.
  • Single-user and self-hosted only. There is no hosted service, no sign-up and no multi-user mode, and none is planned.
  • It does not reply, send, delete, move or archive. By design.
  • It does not read attachment text. Images are read; PDFs and Office files are listed by name and can be sent to you, but their contents are not searched.
  • Answers are as fresh as the last run. Send /sync to fetch new mail first.
  • Links can go stale. Outlook usually gives an email a new id when you move it to another folder, so ↗ links and attachment buttons for moved mail may stop working.
  • AI output can be wrong. A category, a date or an answer may be mistaken. Sources are always shown so you can check.
  • You will need to sign in again sometimes. How often depends on your organisation's settings.
  • Autostart is Windows only. Elsewhere, use Docker or your own service manager.

Questions

Does it need admin approval or an app registration?

It uses the Outlook web session you already have; no app registration is needed. That is a technical fact, not permission. Whether you may automate your mailbox and send its text to an AI endpoint and Telegram is decided by your organisation's policy, so check it before you start.

Will it mark my emails as read?

No. It reads mail through read-only calls without opening anything, so unread mail stays unread. Tapping a ↗ link opens the email in Outlook, which marks it read as Outlook always does.

Which AI models do I need?

Any OpenAI-compatible endpoint: one your organisation runs, a hosted provider, or a local server such as Ollama. It needs a chat model for classifying, one that accepts images, a stronger chat model for the digest and for answers, and an embedding model for search. One capable vision model can fill all the chat roles. The model must return JSON reliably and must not refuse to summarise your own email, so try it on a few messages first.

What does it cost?

MailBrief is free. Telegram bots are free. You pay whatever your AI endpoint charges: about one call per new email, one per digest, and two per chat question, plus embeddings.

Does it work on macOS or Linux?

It was built and is used on Windows, and it also runs in the Docker image, which is Linux. The code is plain Python with Playwright, so macOS should work, but that is not regularly tested. mailbrief autostart is Windows only.

Can I run it on a server instead of my PC?

Yes, with the Dockerfile in the repository, on a server of your own. The setup guide covers it. The command reference also has recipes for two rented cloud hosts; read the warning there first, because such a host holds both your encrypted data and the key, and sign-ins from data-centre addresses tend to expire sooner.

Can I host it for my friends or my team?

No. MailBrief is built for exactly one person and has no accounts or separation between users. Holding other people's mailbox sessions and email brings legal duties a personal project cannot carry, so that was deliberately left out. Each person would run their own copy.

How do I remove everything it did?

uv run mailbrief labels clear --all --colours removes every MB: label and deletes the MB: categories from your category list. Then stop the service, turn off autostart, delete the project folder (which contains data/), and revoke the bot token in @BotFather.

What happens if I lose the encryption key?

The saved session and archive cannot be read. You generate a new key, sign in again, and rebuild the archive from Outlook with mailbrief run --backfill. Saved digests are gone; your email is untouched.
