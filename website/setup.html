From clone to your first digest

Follow the steps in order. Steps 1 to 8 give you a working morning digest in Telegram. Step 9 onwards is optional: history, chat search, and running on a schedule.

Every uv run … line below works the same in bash (Linux, macOS, Git Bash) and Windows PowerShell. Where the shells differ, both versions are shown.

Before you start. MailBrief is a personal project for one person and their own mailbox. It uses Outlook on the web's internal interface, not a public API, so it can break or be blocked. Automated access may be against your organisation's IT policy: check first. Email text is sent to the AI endpoint you choose, and digests and chat answers go to Telegram.

  1. Check the requirements

    • A Microsoft 365 work or school account that you read in Outlook on the web (outlook.office.com). Personal Outlook.com accounts are not supported.
    • An OpenAI-compatible AI endpoint serving a chat model, a model that accepts images, and an embedding model. Use one your organisation runs, or a local server such as Ollama. There is no default endpoint.
    • A Telegram account. You create your own bot in step 5.
    • Python 3.11, uv and git, on Windows, Linux or macOS. For an always-on server, Docker. Windows and the Linux Docker image are the established paths; macOS is not regularly tested.

    To look around first, the offline tour needs no account and no key: run uv sync, then uv run python demo/run.py. It uses 15 invented emails in a temporary archive.

  2. Clone and install

    git clone https://github.com/KidCoderT/mail-manager.git
cd mail-manager
uv sync
uv run playwright install chromium --no-shell

    uv sync installs the pinned dependencies into .venv/. The second command downloads the Chromium build Playwright drives (about 200 MB). Run it again after upgrading the playwright package.

  3. Create .env and an encryption key

    Copy the example file:

    bash

    cp .env.example .env

    PowerShell

    Copy-Item .env.example .env

    Generate a key. This line is the same in both shells:

    uv run python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

    Paste the output after SESSION_ENCRYPTION_KEY= in .env.

    Keep this key safe. It decrypts your saved Outlook session and your email archive. If you lose it, both are unreadable: you sign in again and the archive is gone.

  4. Point it at your AI endpoint

    Set these in .env. Use the model names exactly as your endpoint lists them. The defaults shown are the ones this project was tested with.

    VariableWhat it isExample / default
    AI_BASE_URLThe OpenAI-compatible endpoint. Required: your email text is sent here.http://localhost:11434/v1
    AI_API_KEYThe endpoint's key. Leave it empty for a local server with no authentication.(empty)
    AI_CLASSIFIER_MODELClassifies text-only emailsqwen3.6:35b
    AI_VISION_MODELClassifies emails with images (must accept images)qwen3.6:35b
    AI_DIGEST_MODELWrites the digestqwen3.8:27b
    AI_ANSWER_MODELWrites chat answersqwen3.8:27b
    AI_EMBED_MODELEmbeddings for the chat search indexbge-m3
    AI_CHAT_TEMPLATE_KWARGSon only for Qwen/Ollama servers that accept enable_thinking. Keep off for strict OpenAI-compatible servers.off
    AI_FALLBACK_MODELUsed when another model doesn't answer in time. Empty means never switch.AI_CLASSIFIER_MODEL

    Also set DEFAULT_TIMEZONE to your IANA timezone, for example Europe/London (default Asia/Singapore). AI_API_KEY and TELEGRAM_BOT_TOKEN may live in .env or in user environment variables. Every other setting is listed in the configuration reference.

  5. Create your Telegram bot

    1. In Telegram, open @BotFather and send /newbot. Follow the prompts.
    2. Copy the token it gives you into .env as TELEGRAM_BOT_TOKEN=….
    3. In BotFather, send /setjoingroups, pick your bot, choose Disable. Nobody can then add your bot to their groups.

  6. Sign in to Outlook once

    uv run mailbrief login

    A browser window opens on Outlook. Sign in as usual (password, MFA) and tick Stay signed in. When your inbox is visible, press Enter in the terminal. The session is saved, encrypted, to data/session.enc. No email is read during login.

    Sign in on the same machine that will run the daily job. On a server with no screen, use mailbrief login --remote instead (see login).

  7. Register your chat as the destination

    First send your bot any message in Telegram, so it can find your chat. Then:

    uv run mailbrief add-destination telegram

    Pick your chat by number. It is saved to data/destinations.json and a test message arrives. Only chats added this way get digests or chat answers. If you already know your chat ID, --chat-id 123456789 skips the lookup (no test message).

  8. Get your first digest

    uv run mailbrief run --send --commit

    This reads mail from the last 24 hours, classifies it, saves it to the encrypted archive, puts MB: categories on those emails in Outlook, and sends the digest to Telegram. --commit marks them as processed, so tomorrow's run starts from here.

    Want a dry look first? uv run mailbrief run prints the digest without sending it or marking anything processed. It still saves to the archive and labels the emails in Outlook. To turn labelling off, set OUTLOOK_LABELS=off.

    What MailBrief changes in Outlook: only its own MB: categories. It never deletes, moves, sends, replies to, or marks anything as read. A code-level check refuses every other kind of write.

  9. Optional: archive your history and enable chat search

    Do this after the first digest:

    uv run mailbrief run --backfill
uv run mailbrief index rebuild
uv run mailbrief chat "any deadlines this week?"

    --backfill saves your whole inbox to the archive and moves the cursor to the newest email. Run it first and nothing is left "new", so your first run --send --commit would only say No new emails, so no digest. It is resumable: Ctrl+C keeps what's done, and running it again continues.

    index rebuild embeds the archive for chat search (it sends email text to your AI_EMBED_MODEL). After that, every run keeps the index current by itself.

  10. Optional: run it every morning

    serve runs forever, fires a run at each RUN_AT time (default daily 07:30) and answers your Telegram chat.

    uv run mailbrief serve

    Try a different schedule without editing .env:

    uv run mailbrief serve --at "daily 07:30; sun 20:00 this-week"

    Stop it with Ctrl+C, or uv run mailbrief stop from another terminal. A run in progress finishes first. The schedule format is in RUN_AT.

    Windows: start hidden at logon

    uv run mailbrief autostart on
schtasks /Run /TN MailBrief
uv run mailbrief status

    The first line creates a Task Scheduler task named MailBrief, the second starts it now without logging out, the third checks it. uv run mailbrief autostart off removes the task. No admin rights needed. On Linux and macOS use Docker or your own service manager.

    Watch the log

    There is one file per month in data/logs/. Replace the month in the file name with the current one.

    bash

    tail -f data/logs/2026-11.log

    PowerShell

    Get-Content data\logs\2026-11.log -Wait -Tail 30

    A server with Docker

    Put the same .env on the server (add AI_API_KEY there if it is a Windows variable on your PC). Copy data/session.enc and data/destinations.json into ./data/; this needs the same SESSION_ENCRYPTION_KEY.

    git clone https://github.com/KidCoderT/mail-manager.git
cd mail-manager
docker compose up -d --build
docker compose logs -f
docker compose exec mailbrief mailbrief status

    Stop it properly with docker compose down. Update with git pull, then docker compose up -d --build. With no screen on the server, sign in by sending /login to your bot. Railway and Render are covered in Hosting; read the privacy note there first.
