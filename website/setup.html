Set it up

From git clone to your first digest in Telegram, then to a schedule that runs by itself. Follow the steps in order: two of them depend on what came before.

Before you start. MailBrief is unofficial and uses an undocumented Outlook on the web interface. It sends your email text to the AI endpoint you configure, and summaries to Telegram. Check your organisation's IT acceptable-use policy first, and read the limits and privacy notes.

  1. What you need

    • A Microsoft 365 work or school account whose mail you read in Outlook on the web. Personal Outlook.com accounts are not supported.
    • A computer you sign in from normally. Do the setup on the machine that will run the daily job: moving a saved session between machines or networks often forces a new sign-in.
    • git and uv. uv manages the Python environment and installs Python 3.11 for the project if you do not have it.
    • An OpenAI-compatible AI endpoint and a key for it: one your organisation runs, a hosted provider, or a local server such as Ollama. It must offer:
      • a chat model (classifying, digests, answers),
      • a model that accepts images (posters and screenshots in emails; this can be the same model),
      • an embedding model (search for the inbox chat).
    • A Telegram account. You will create your own bot with @BotFather in step 4.
    • About 200 MB of disk for the browser MailBrief drives.

  2. Get the code and install

    git clone https://github.com/KidCoderT/mail-manager.git
cd mail-manager
uv sync
uv run playwright install chromium --no-shell

    uv sync creates .venv/ and installs the dependencies pinned in uv.lock. The last command downloads the Chromium build that Playwright drives. Every later command is run from this folder with uv run.

    Check that it works:

    uv run mailbrief --help

  3. Create .env

    Copy the example file. Git ignores .env, so your keys stay out of the repository.

    # macOS, Linux, Git Bash
cp .env.example .env
    # Windows PowerShell
Copy-Item .env.example .env

    Generate the encryption key

    uv run python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

    Paste the output after SESSION_ENCRYPTION_KEY=. This key encrypts your Outlook session, your email archive and the search index. Keep a copy somewhere safe: without it they cannot be read, and you would have to sign in and backfill again.

    Fill in the settings

    The example file leaves the endpoint empty and includes example model names. Set the URL and replace the model names with ones your endpoint serves. The fallback model is optional.

    # AI: any OpenAI-compatible endpoint. The URL usually ends in /v1
AI_BASE_URL=https://ai.example.com/v1
AI_API_KEY=your-api-key
AI_CLASSIFIER_MODEL=your-fast-chat-model
AI_VISION_MODEL=your-vision-model
AI_DIGEST_MODEL=your-strong-chat-model
AI_ANSWER_MODEL=your-strong-chat-model
AI_EMBED_MODEL=your-embedding-model
AI_FALLBACK_MODEL=your-fast-chat-model
# Enable only for Qwen/Ollama servers that accept this extension
AI_CHAT_TEMPLATE_KWARGS=off

# from @BotFather (step 4)
TELEGRAM_BOT_TOKEN=paste-the-bot-token-here
# from the command above
SESSION_ENCRYPTION_KEY=paste-the-generated-key-here

# times, the schedule and --day use this zone (an IANA name)
DEFAULT_TIMEZONE=Europe/London
RUN_AT=daily 07:30

OUTLOOK_LABELS=on
REMOTE_IMAGES=on
EVENTS_DAYS=14
CHAT=on
ARCHIVE_DAYS=0
    SettingWhat it does
    AI_CLASSIFIER_MODELClassifies text-only emails and plans chat searches. A fast model is enough.
    AI_VISION_MODELClassifies emails that have images. MailBrief sends at most 4 images per email.
    AI_DIGEST_MODEL, AI_ANSWER_MODELWrite the digest and the chat answers. Use your strongest model.
    AI_EMBED_MODELTurns emails and questions into search vectors. Changing it later rebuilds the index.
    AI_FALLBACK_MODELUsed when another model gives no answer in time. Leave the value empty to never switch.
    OUTLOOK_LABELSoff stops MailBrief from labelling mail in Outlook.
    REMOTE_IMAGESoff stops downloads of images that emails link to. The servers hosting them otherwise see your IP address.
    EVENTS_DAYSHow far ahead the events calendar looks. 0 stops it being sent.
    CHAToff makes the bot send-only: no questions, no commands.
    ARCHIVE_DAYS0 keeps saved mail forever. A number drops months that ended more than that many days ago.

    For a local Ollama server the URL is typically http://localhost:11434/v1. Leave AI_API_KEY empty if your server does not require authentication. Set AI_CHAT_TEMPLATE_KWARGS=on only if your server accepts Qwen's thinking switch.

    Test the model first. It has to return JSON reliably and must not refuse to summarise your own email. A plain mailbrief run in step 7 is a safe way to find out: it sends nothing to Telegram and marks nothing as processed.

  4. Create your Telegram bot

    1. In Telegram, open a chat with @BotFather and send /newbot. Choose a name and a username.
    2. Copy the token it gives you into .env as TELEGRAM_BOT_TOKEN=. The token is a password: whoever has it controls the bot.
    3. Still in @BotFather, send /setjoingroups, pick your bot, and choose Disable, so nobody can add it to a group.
    4. Open your new bot's chat and send it any message, for example "hello". It will not answer yet. Step 6 uses this message to find your chat.

  5. Sign in to Outlook

    uv run mailbrief login
    1. A browser window opens on Outlook on the web.
    2. Sign in as you normally do, including any second factor, and tick Stay signed in.
    3. When you can see your inbox, go back to the terminal and press Enter.

    MailBrief saves that browser session, encrypted, to data/session.enc. Later runs reuse it without showing a window. Your password is typed into Microsoft's own page and is never seen or stored by MailBrief. No email is read during this step.

    You will repeat this command whenever a run reports that the session has expired. How often that happens is set by your organisation.

  6. Register your chat

    uv run mailbrief add-destination telegram

    It lists the chats that recently messaged your bot. Pick yours by number. MailBrief saves it and sends a test message there:

    ✅ MailBrief will send your morning digest here.now

    This is the only way a chat can be added. It decides both where digests go and who the bot will answer.

    If it finds no chats, send your bot another message and run it again. If you already know your chat id, --chat-id 123456789 skips the lookup. Do not run the lookup while mailbrief serve is running: stop it first with mailbrief stop.

  7. Send the first digest

    Preview first. This reads the last 24 hours of mail, classifies it, labels it in Outlook and prints the digest in the terminal. It sends nothing and marks nothing as processed, so you can repeat it.

    uv run mailbrief run

    When the output looks right, do it for real:

    uv run mailbrief run --send --commit

    --send delivers the digest and the events calendar to Telegram. --commit marks those emails as processed, so the next run only covers newer mail. Emails classified in the preview are not sent to the AI again.

    • If nothing arrived in the last 24 hours it prints No new emails, so no digest. Try again tomorrow, or continue with step 8.
    • To keep labels out of Outlook while you try things, set OUTLOOK_LABELS=off first. To remove labels afterwards: uv run mailbrief labels clear --all --colours.

    Do this step before the backfill. The backfill in step 8 moves the "processed up to here" marker to your newest email. Run it first and your first digest has nothing left to report.

  8. Backfill and build the index

    So far MailBrief only knows the last day of mail. To let the chat answer questions about older email, save the whole inbox once, then build the search index.

    uv run mailbrief run --backfill
uv run mailbrief index rebuild
    • The backfill makes one AI call per email it has not seen, so a large inbox takes a while and costs whatever your endpoint charges. It sends no digest.
    • It saves every 25 emails. Ctrl+C keeps what is done, and running it again continues where it stopped.
    • Saved inbox emails get their labels in Outlook too, up to 400 per run, unless OUTLOOK_LABELS=off.
    • index rebuild sends email text to your embedding model and stores only vectors, encrypted, in data/index.enc. After this, every run keeps the index current by itself.

    Try a question in the terminal:

    uv run mailbrief chat "what is due this week?"

  9. Run it on a schedule

    mailbrief serve is one long-running process. It starts a run at each RUN_AT time and answers your Telegram chat in between. Pick one of the three ways to keep it running.

    In a terminal

    uv run mailbrief serve

    It runs until you press Ctrl+C or close the window. Good for the first day. Message your bot a question while it is running.

    Automatically on Windows

    uv run mailbrief autostart on
schtasks /Run /TN MailBrief
uv run mailbrief status

    The first command creates a Task Scheduler task named MailBrief that starts serve, hidden, each time you log in. It needs no admin rights. The second starts it now. If the PC was off or asleep at the scheduled time, the missed run happens once it is back.

    # stop it now / stop it starting at logon
uv run mailbrief stop
uv run mailbrief autostart off

    In Docker, on a server of your own

    The repository has a Dockerfile and a compose.yaml that run the same serve as a non-root user and restart it after crashes and reboots. The simplest route is to finish steps 1 to 8 on your PC, then move the result:

    1. Clone the repository on the server.
    2. Copy your .env and your data/ folder into it. The SESSION_ENCRYPTION_KEY must be the same one that encrypted the data.
    3. Edit the TZ: line in compose.yaml to your time zone.
    4. Start it.
    docker compose up -d --build
docker compose logs -f
docker compose exec mailbrief mailbrief status
docker compose down
    • .env and data/ are passed in at run time and are not baked into the image. The image needs about 2 GB of disk.
    • Microsoft may ask you to sign in again when the session shows up from a new machine or network. A server has no screen, so that sign-in goes through /login in Telegram, which needs the ports: line in compose.yaml uncommented and PUBLIC_URL set to an https:// address that reaches it (a reverse proxy or tunnel with TLS). The details are in commands.md, section 2.
    • A rented cloud host holds your archive, your session and the key that decrypts them. Treat that as handing your mail to a third party, and check your organisation's policy before choosing it.

  10. Make it yours

    Tell MailBrief who you are and what you care about. These rules add your own labels and decide what gets a ⭐ in the digest.

    uv run mailbrief rules profile "Second-year biology student looking for lab internships and research talks"
uv run mailbrief rules add course BIO204
uv run mailbrief rules add sender ivastari@example.edu --label "Dr Vastari" --direct --priority 1
uv run mailbrief rules add topic Research "lab openings, research talks, summer studentships" --priority 2
uv run mailbrief rules list

    More on labels, the schedule format, and the everyday commands.

If something goes wrong

You seeWhat to do
No saved session. Run `mailbrief login` first.Do step 5.
Outlook session expired. Run `mailbrief login` again.Sign in again with uv run mailbrief login. This is normal from time to time.
AI_BASE_URL is not set or an AI authentication errorSet your endpoint in .env and, if it requires authentication, its AI_API_KEY.
AI: no answer from … in a slow runYour endpoint or network is not responding. Each call gives up after two retries; a scheduled run retries by itself.
Another MailBrief run is in progress…A scheduled run or another terminal is using Outlook. Wait for it to finish.
MailBrief is already runningA serve is already active. Check with uv run mailbrief status.
A digest did not arriveuv run mailbrief emails --digest --send resends today's saved digest without calling the AI.
Emails come back as UnclassifiedThe model did not return usable JSON. They are retried on later runs for 7 days; consider a different model.
